# UX/UI Design Principles for Codex

## What Works

- Start from the user task and make the primary action obvious.
- Use hierarchy before decoration: layout, type scale, spacing, contrast, grouping.
- Reuse the local design system: tokens, components, variants, and established page patterns.
- Design states as part of the component: default, hover, focus-visible, disabled, loading, empty, error, and success.
- Keep operational SaaS interfaces calm, scannable, and dense enough for repeated work.
- Use semantic color: action, success, warning, destructive, muted, border, surface, background.
- Use progressive disclosure for advanced or rare actions.
- Prefer predictable components: Button, Input, Label, Select, Dialog/Sheet, DropdownMenu, Tabs, Badge, Alert, Skeleton, Table, Tooltip.

## What Usually Fails

- Asking for "modern" or "beautiful" without specifying hierarchy, spacing, state handling, and accessibility.
- Adding gradients, glass effects, shadows, oversized cards, and decorative icons to hide weak structure.
- Creating a new visual language instead of reading the existing app.
- Making every section a card.
- Using low-contrast gray text for important content.
- Forgetting mobile layout and keyboard/focus behavior.
- Changing business logic while doing a visual refactor.
